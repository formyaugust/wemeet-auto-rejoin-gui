# wemeet-auto-rejoin-gui
解决腾讯会议免费时长40分钟到期后重新进入会议的问题
# 腾讯会议 —— 掉线自动重进 使用说明

> 免费版单场会议 40 分钟到点后，会议会自动结束、所有人被踢出。
> 这个小工具的作用是：**检测到会议结束就自动用同一个会议号重新进去**，不用你手动开客户端、输号码、点加入。

---

## 一、快速开始（三步）

> ### ⚠️ 先看这一条：如果「点了没反应」，是完整性标签问题
>
> 程序启动时会在日志第一行打印 **本进程完整性级别**。
>
> - 显示 **`中 (Medium)`** → 正常，往下看
> - 显示 **`低 (Low)`** → **点击和键盘输入会被 Windows 拦掉**（能识别窗口、能切前台，就是点了没反应）
>
> 修复办法（二选一）：
>
> **A. 复制文件夹（推荐，一定能解决）**
> 1. 在桌面或 D 盘新建一个文件夹，例如 `D:\腾讯会议自动重进`
> 2. 把本文件夹里的文件**用资源管理器复制**过去（是复制，不是移动）
> 3. 从新文件夹运行 exe
>
> **B. 运行 `修复完整性标签.cmd`**
> 双击它，脚本会尝试把标签提升为 Medium 并验证结果。失败时会提示你改用办法 A。

1. 打开 **腾讯会议**，让它保持能正常打开的状态（不要求停在某个页面）
2. 双击 **`腾讯会议自动重进.exe`**
3. 确认界面上的参数后，点 **「开始监控」**，然后把窗口最小化挂着即可

程序会每 5 秒检查一次"当前是否在会议中"。一旦发现你已经掉线，就自动重进。

> **第一次使用请先做第「四」节的校准**，两分钟，能避免绝大多数"点了没反应"的问题。

## 二、界面参数说明

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| **会议号** | （留空，自己填） | 只填数字，横杠可以省略（`123456789` 和 `123-456-789` 等价） |
| **掉线判定(秒)** | 20 | 连续多少秒检测不到会议，才判定为"已掉线"。太小容易误判（比如切换窗口的瞬间），太大则重进变慢。建议 15~30 |
| **轮询间隔(秒)** | 5 | 每隔多久检查一次。**轮询是纯只读操作**（只列举窗口），不会置顶、不会抢焦点 |
| **重进间隔(秒)** | 90 | 两次重进尝试之间的最短间隔，防止疯狂重试 |
| **最大尝试次数** | 3 | 每次掉线最多自动重进几次。到上限就停手，**避免你主动退出会议后被反复拽回去** |
| **重进方式** | 界面点击 | 见下节 |
| **测试模式** | 关 | 勾选后只做到"点开入会界面并输入会议号"，**不按回车**，用来验证点击位置准不准 |
| **启动后自动开始监控** | 关 | 勾选后打开程序即开始工作，适合放进开机启动 |
| **客户端路径** | 自动检测 | 点「自动检测」会读取注册表里 `wemeet:` 协议的位置，最可靠 |
| **点击位置 X / Y** | 309 / 250 | 「加入会议」磁贴中心，**相对客户端窗口左上角**。⚠️ **通常不需要手工填** —— 程序每次重进前都会截图自动识别按钮位置；这两个值只是识别失败时的兜底。点旁边的「自动定位按钮位置」可立即识别并写回 |

界面上的每个控件都有**鼠标悬停提示**，鼠标停一下就能看到详细解释。

## 三、三种重进方式

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| **界面点击**（推荐） | 把客户端切到前台 → 点「加入会议」磁贴 → 输入会议号 → 回车 | 最接近真人操作，成功率最高；依赖坐标，客户端改版后可能需要重新校准 |
| **深链唤起** | 发送 `wemeet://page/join_meeting/init?meeting_code=会议号` 给客户端 | 不碰鼠标键盘，最"干净"；但依赖客户端支持该路由，**实测在托盘状态下未唤起窗口**，可靠性存疑 |
| **键盘盲打** | 把客户端切到前台 → 直接输入会议号 → 回车 | 不依赖任何坐标；但要求客户端当时正好停在能接收输入的页面 |

程序默认用「界面点击」。如果发现点了没反应，可以换另外两种试试。

## 四、首次使用务必做的两步校准

### 第 1 步：确认"窗口识别"认得你的会议

点 **「测试窗口识别」**，日志里会列出当前所有属于腾讯会议的窗口和判定结果。

- **你没开会时**：应该显示 `判定：在会议中 = 否`
- **你正在开会时**：应该显示 `判定：在会议中 = 是`

如果开会时它仍显示"否"，说明识别规则没认出来，请把那段日志发我调整。

> **识别规则**
>
> 1. 窗口所属进程的可执行文件必须是 **`WeMeetApp.exe`**（或与界面上填写的客户端路径完全一致）；
> 2. 存在一个标题**不是**「腾讯会议」（主界面）也不是「WeMeetApp」（隐藏窗口）的客户端窗口；
> 3. 并且它 **要么正常显示且尺寸够大，要么处于最小化状态**。
>
> **第 3 条里的"最小化也算"很关键**：Windows 的 `IsWindowVisible` 对最小化的窗口返回 false，
> 如果只认可见窗口，你把会议窗口最小化就会被误判成"已掉线"并触发重进。
>
> 实测在会议中时，会议窗口标题是**会议主题**（例如「张三的会议」）。
> 隐藏的辅助窗口（`XNNWndCls_*`、`Chrome_WidgetWin_0`、`Qt680ScreenChangeObserverWindow` 等）
> 因为既不可见也没最小化，会被自动排除。

**命令行自检**：不想点界面的话，可以直接跑一次识别并把结果写成文件：

```
腾讯会议自动重进.exe --probe
```

它会把当前所有腾讯会议窗口和判定结果写进同目录的 `probe-result.txt`，不开界面。

### 第 2 步：确认"加入会议"按钮定位得准

**现在按钮位置是自动识别的**，一般不需要手工调。想确认或重新定位：

1. 打开腾讯会议，**停在首页**（能看到「加入会议」那个界面）
2. 点 **「自动定位按钮位置」**

程序会：切前台 → 截图 → 识别蓝色方块磁贴 → 在弹出的提示里告诉你结果，并把带**红圈十字标记**的预览图存成 `detect-preview.png`。**打开那张图看一眼**，红圈落在「加入会议」上就说明对了。

也可以命令行跑：
```
腾讯会议自动重进.exe --detect
```
结果写进 `detect-result.txt`，预览图同上，不开界面。

**识别原理**：客户端首页有 5 个蓝色圆角方块磁贴，实测都是 124×124 的正方形；而其它蓝色元素都不是正方形（会议列表里的「入会」按钮是 124×44 的扁条形、左侧栏图标只有 36×24）。所以规则是：**找出接近正方形的蓝色块，取最靠左上的那块** = 「加入会议」。这样窗口大小、位置、磁贴间距变了都能自动适应。

> **注意：你已经在会议里时，首页布局会变**
>
> | 位置 | 不在会议中 | 在会议中 |
> | --- | --- | --- |
> | 第一个磁贴 | 加入会议（亮蓝） | **返回会议（橙色）** |
> | 第二个磁贴 | 快速会议 | **加入会议（暗蓝、禁用态）** |
> | 会议列表按钮 | 入会 | **已入会** |
>
> 橙色不会被识别成蓝色磁贴，所以这时"最靠左上的蓝色方块"会正确地落到第二个位置的「加入会议」上。
> 但请注意：**这个按钮此时是禁用状态**，点了不会有反应 —— 这是正常的，因为你本来就在会议里。
> 换句话说，如果你看到程序在"会议中"状态下尝试点击，说明判定出了问题，应该先排查识别规则。

如果自动定位失败，程序会**自动退回**「点击位置 X / Y」里填的参考坐标，并在日志里说明原因。

> **为什么之前要手工量**：旧版本用固定坐标，而且开发环境是受限沙箱，注入的鼠标点击会被系统 UIPI 机制丢弃，无法在开发侧验证。现在改成截图识别，就不再依赖手工坐标了。

### 第 3 步：端到端试一次（可选，但推荐）

确认按钮定位对了之后，可以完整走一遍点击流程：

1. 打开腾讯会议，**停在首页**
2. 勾选 **「测试模式」**（只做到输入会议号，**不按回车**，不会真的进会议）
3. 点 **「立即重进一次」**

看着屏幕确认：入会界面弹出来了、会议号也填进去了。这样就说明整条链路没问题，取消「测试模式」即可正式使用。

> 这一步仍然建议做一次，因为它验证的不只是坐标，还有「点击能不能被客户端接收」。如果你曾经以管理员身份运行过本程序、而腾讯会议是普通权限，Windows 会拦截这种注入 —— 那种情况下点击会没反应。**两个程序保持同样的普通权限即可。**

## 五、工作原理

```
每 5 秒：列举窗口（只读）→ 判断是否在会议中
                    │
         在会议中 ──┴── 不在会议中
            │                │
       重置计数          累计"缺席"秒数
                              │
                    连续缺席 ≥ 掉线判定秒数
                              │
                    未超过最大尝试次数、且过了重进间隔
                              │
                    ▼ 此时才切前台 + 点击/输入（会短暂抢一下焦点）
```

**关键设计**：轮询阶段完全不碰前台，只做 `EnumWindows` 这类读操作。只有真正要重进的那一刻，才会把客户端窗口提到最前面 —— 所以它不会在你正常用电脑时反复弹窗抢焦点。

## 六、常见问题

**Q：点击完全没反应（窗口能识别、也能切前台，就是不点）**

这是**完整性标签**问题，也是最常见的坑。看日志第一行：

```
本进程完整性级别：低 (Low)      ← 有问题
本进程完整性级别：中 (Medium)   ← 正常
```

Windows 有一条安全规则叫 **UIPI（用户界面特权隔离）**：低完整性进程**不允许**向普通（中）完整性进程注入鼠标点击和键盘输入。而腾讯会议是普通权限运行的，所以点击会被系统**静默丢弃** —— 没有任何报错，看起来就像"什么都没发生"。

**为什么会带上 Low 标签**：任何由受限进程、沙箱进程、部分下载工具创建的文件，都会被 Windows 自动打上 Low 完整性标签。**注意这个标签会"传染"**：如果所在文件夹也是 Low，之后在里面新建的文件同样继承 Low。

**怎么修**：见第一节的两种办法（复制文件夹 或 运行 `修复完整性标签.cmd`）。用资源管理器把你自己的普通权限进程复制出来的文件，标签会恢复正常。

**怎么自己检查**：在文件上右键看不出这个标签，需要用命令行：

```
icacls "腾讯会议自动重进.exe"
```

输出里出现 `Mandatory Label\Low Mandatory Level` 就是中招了；没有这一行、或显示 `Medium` 就正常。

**Q：程序显示"未确定客户端路径"**
点「自动检测」。它会读注册表里 `wemeet:` 协议（`HKLM\SOFTWARE\Classes\wemeet\shell\open\command`），这是客户端安装时自己写的，最准。实在不行手动填写，例如 `C:\Program Files\Tencent\WeMeet\WeMeetApp.exe`。

**Q：一直显示"会议中"，其实我没开会**
点「测试窗口识别」，看日志里哪个窗口被误判了，欢迎提issue。

**Q：点击了但没进会议**
1. 确认「测试模式」已取消（勾着的话不会按回车）
2. 用「测试模式」确认坐标点得准
3. 换个「重进方式」试试
4. 如果会议号对应的会议**已经彻底结束**，那谁也进不去 —— 只有主持人重新发起后才能进

**Q：我主动退出会议了，它把我拽回去了**
把「最大尝试次数」调小（比如 1），或者直接点「停止」。程序分不清"被踢"和"主动退出"，这是目前的设计限制。

**Q：日志在哪**
程序同目录的 `rejoin.log`，界面里也会实时显示。

**Q：设置保存在哪**
程序同目录的 `config.ini`。在界面上改完点「保存设置」即可写回；也可以直接编辑这个文件。注意 exe 所在目录要可写（放在 `C:\Program Files` 下可能写不进去）。

## 七、已知限制

1. **"在会议中"的判定基于窗口标题**：如果腾讯会议改版后，开会的窗口标题也变成了「腾讯会议」，判定就会失效。届时用「测试窗口识别」一看便知。
2. **点击坐标依赖客户端界面布局**：客户端大版本更新可能挪动「加入会议」的位置，需要重新校准 X/Y。
3. **分不清"被踢出"和"主动退出"**：只能靠「最大尝试次数」兜底。
4. **会议需要能重新进入**：如果 40 分钟到点后会议被彻底终止且主持人没有重新发起，任何工具都进不去。
5. **需要和客户端同等权限**：请以普通用户身份运行（和腾讯会议一致）。右键"以管理员身份运行"反而可能导致输入注入被 Windows 拦截。

## 八、免责说明

本工具只是**自动化你自己电脑上的客户端**，替你完成"手动重新点加入会议"这个动作，不涉及破解、不修改客户端、不绕过任何技术保护。

但请注意：
- 腾讯的用户协议对第三方自动化可能有约束，是否使用请自行判断；
- 免费版时长限制本身是产品策略，本工具不改变单场会议仍受 40 分钟限制这一事实。
